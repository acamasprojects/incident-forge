# Contributing

This is a one-person hobby project, but it still follows a simple workflow to keep `main` clean and the history easy to follow.

1. New features or fixes start as a GitHub Issue describing what's being added or fixed.
2. Work happens on its own branch, made from `main`, named after the issue (for example `3-scenario-editor`).
3. When it's ready, it goes up as a Pull Request that references the issue (for example "Closes #3").
4. The repo owner reviews and merges the PR. Nothing gets pushed straight to `main`.

No CI pipeline or required approvals beyond that review, just a clean record of what changed and why.
